## Session 01 — full illustrated rollout (2026-10-26)

- Extended `/dev/layout-editor` (the dev-only visual positioning tool from the illustration prototype) beyond text-block dragging: draggable anchor/control handles for every hand-drawn line (name bracket, callout stems, gossip squiggle, pushpin, paperclip, current-tag zigzag), rendered in zoomed mini-canvases so dragging is precise even though these shapes are tiny on the real site, plus a max-width field per callout slot. Replaced the old copy-to-clipboard handoff with a "Save to file" button (Madhura: "I don't want to copy edited code back") backed by a new dev-only API route (`src/app/api/dev/layout-editor/save/route.ts`, 404s outside development) that writes edited state to a gitignored local file for direct reading and implementation — no manual copy-paste. Found and fixed two real interaction bugs while building it: adjacent handles' invisible hit-circles overlapped so paint order (not click proximity) decided which handle a click grabbed (fixed by shrinking the hit radius), and the bracket/stem handles were occluded by the name heading painting on top of them in DOM order (fixed with a scoped `z-index`).
- Drafted `recordFacts` (the numbered-callout captions) for the 24 guests that didn't have them yet — king was the only one done in the prototype session. Verbatim-derived short phrases split from each guest's existing `recordText`, nothing invented.
- Rolled out the full illustrated template (prototyped on king alone last session) to all 25 word pages: the name zone with record-fact callouts and bracket/stem lines, the gossip squiggle, the pinned testimony card, and the relatives zone with connector lines to place-card links. `placement.ts` gained `CalloutSlot` (with a per-slot `maxWidth`, fixing a real clipping bug where kriss-kringle's long `Christkindlein: "Christ child"` fact overflowed its slot) and exports every hand-drawn path as a named constant so `/dev/layout-editor` edits the live numbers instead of a hand-copied duplicate.
- Reviewed `Table.html`/`Desktop-Table.html` and built the illustrated table page: the one real table drawing that exists (Head table), reused across all 5 tables with a small procedural tilt per table rather than inventing 4 more hand-drawn shapes, place cards distributed around its edge, per-guest object placeholders, and one floater cameo line per table (`getFloatersAt` in `data.ts`, driven by each floater's `seenAt`). Left out the manicule/snippet-pointer treatment and the pinned evidence card — both belong to the not-yet-built evidence-row/verdict feature, confirmed with Madhura rather than guessed. Found and fixed a real clipping bug: long guest names (kindergarten, wunderkind) overflowed both the drawing canvas and a 360px viewport because the place card had `white-space: nowrap` instead of wrapping like the word page's cards already do. `tablePlacement.ts` (new) holds the oval shape and a circular place-card layout — the table-page counterpart to `RELATIVE_SLOTS`, needed because guest count varies per table. `seedFloat` extracted to `seed.ts` so both placement engines share it instead of duplicating it.
- Reviewed `Main.html`/`Desktop-Main.html` and built the illustrated hall page: all 5 tables as small ovals in a fixed layout (positions copied from the one hall mockup that exists), guest place cards scattered around each, the 4 floaters at their own fixed spots, and a bottom nav strip to any table. Left out, matching CLAUDE.md's locked launch scope: the invitation card and "Find your seat" button ("Not in launch: the invitation feature"), the undecided "1/5" counter widget (CLAUDE.md lists this as still open), and the `*gene-` portrait link (renders as plain text — no `/portrait` page exists yet). Caught and fixed the same class of clipping bug as the table page, this time via a systematic DOM bounding-box check across every card instead of eyeballing screenshots — several guest/floater cards clipped past a 360–390px viewport; fixed by pulling the affected positions inward. `tablePlacement.ts`'s `placeAroundTable` generalized into `placeOnOval` so the hall page's small clusters and the full table page share the same circular-placement math.
- Madhura: the hall page's desktop view was wrong — didn't match `Desktop-Main.html`. Root cause: the desktop layout had been built as a CSS `transform: scale(1.5)` of the phone layout's narrow single-column arrangement, which just put a skinny column in the middle of a wide screen instead of spreading across it — `Desktop-Main.html` turns out to have its own fully hand-authored layout, 5 tables spread across a 1440-wide canvas, the same way `Desktop-Table.html` already did for the table page (not caught at the time since a single oval scaling up doesn't look as obviously wrong as 5 scattered ones did). Fixed by extracting the real desktop oval/floater positions from the mockup and rendering two parallel layouts (`HallMap`, reused for both) toggled by CSS media query instead of a transform. `hallPlacement.ts` gained `HALL_TABLE_SLOTS_DESKTOP`/`FLOATER_SLOTS_DESKTOP`/`nameStyleVariantDesktop`. Verified by comparing directly against the mockup screenshot and a DOM bounding-box check at both 360px and 1440px (60 and 30 elements, zero offenders). **Flagged, not fixed:** the table page's desktop view uses the same unverified scale-transform shortcut — it happened to look acceptable, but hasn't actually been checked against `Desktop-Table.html`'s own numbers the way the hall page now has.
- Madhura: the relatives ("related words") column should be wider and less tall. Widened it (342 → 366px, bled to the page edges like the name zone) and increased per-slot card width (170 → 190-230px). The "less tall" half hit a real content-driven ceiling: a card+caption+pointer group's height is set by its tallest actual content (~150px regardless of width), not by the column's width, so guests filling all 3 slots are only modestly shorter — reported this honestly rather than overclaiming. Guests with 1-2 relative links (most of them) *are* genuinely shorter, partly because this also fixed a real bug: the slot array had drifted out of top-to-bottom order from an earlier layout-editor save, silently breaking the height calculation for low-link-count guests. Also caught a second bug live: a slot's `maxWidth: 2000` (confirmed intentional earlier in the session) let that card's box grow to fill whatever room was available (284px for one real caption) rather than being unconstrained, which broke the 360px-viewport requirement no matter where the slot sat — capped back to 230px with the evidence. Verified by rendering all 25 guests at 360px, 390px, and 1440px, not by computing it.
