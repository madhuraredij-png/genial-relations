## Session 01 — illustration prototype (2026-10-23)

- After Gate 4/5 shipped, Madhura reviewed the Vercel preview and asked to bring in the full hand-drawn visual system from the mockups ("I need to look like my mockups") — the SVG filters, numbered-callout name treatment, lined-paper testimony card, and place-card relative links were explicitly out of scope through Gate 5. Agreed approach (her choice): prototype one page first, review, then roll out.
- Added a new, optional `recordFacts: string[]` field to the guest schema (`src/lib/schemas/guest.ts`) for the mockup's numbered circle-callouts near the name. This is **not** the same as `docs/spec.md`'s already-deferred `senses` field: spec.md defines `senses` narrowly as "meanings over time, oldest first," but CLAUDE.md's own visual-system section defines the circle/numbered-callout as a broader **"record fact"** — the mockups mix dates, route-words and related-word facts into the same callouts, not meanings alone. Flagged this disagreement and Madhura chose `recordFacts` as a new, separate field rather than overloading or redefining `senses`. `senses` itself stays deferred, untouched (see BACKLOG.md).
- Filled in `recordFacts` for guest **king** only, as the prototype: three short captions split from `recordText` at its existing sentence boundaries — "late Old English · cyning", `cynn: "leader of the people"`, "kin: undetermined, hardly doubted" — verbatim phrases from the existing data, nothing invented.
- Added `src/lib/text.tsx`: `splitSentences()` (splits `recordText` at its own sentence boundaries, used to pair each `recordFacts` caption with its full verbatim sentence) and `withItalics()` (renders the data files' existing `*word*` convention as `<em>`, a display-only interpretation — the underlying copy is untouched).
- Added `src/lib/placement.ts`: a seeded-hash placement helper so relative-link place-cards and name-zone callouts get a stable, varied layout per guest without hand-authoring coordinates for all 25 — per Madhura's "generate positions programmatically" decision. Candidate slot positions are tuned to the mockup's own layout; per-guest jitter (rotation, border-radius) comes from hashing the guest's slug.
- Added `src/components/SvgFilterDefs.tsx`: the four mockup SVG filters (`wobble`, `pencil`, `crayon`, `crumple`, exact parameters copied from `docs/mockups/Desktop-WordA2.html`) plus a fixed-position, multiply-blended `CrumpleOverlay` paper-texture rect. Shared, so table/hall pages can reuse it in a future gate.
- Built `src/app/prototype/king/page.tsx` + `page.module.css`: a standalone, unlinked route (not part of `generateStaticParams`, doesn't touch `/word/[slug]`) rendering king with the full treatment — numbered record-fact callouts around the name, the full verbatim record sentences in a matching numbered list, pencil-hand gossip with a crayon squiggle underline, a lined-paper testimony card with wobble pushpin + crayon paperclip, and relative links split by type: `blood`/`gossip` links render as place-cards (era font per target guest, programmatic position/rotation), `across-the-room` links render as a plain pointer ("at the kids' table →"), matching the pattern in `docs/mockups/Word.html`. King's `object` field stays a plain dashed placeholder, unstyled — per Madhura's explicit "keep it plain" decision; no drawing exists yet.
- Zero changes to the 24 other word pages, the table pages, or the hall — this prototype is fully additive and isolated at `/prototype/king`, reachable only by typing the URL.
- Verified: `npm run build` passes (39 static routes now, +1 for the prototype route); existing `/word/king`, `/`, and `/table/head-table` still return `200` unaffected; Playwright screenshots at 390px and 1440px show 0px horizontal overflow at both widths.
- Found and fixed a page-width bug during this work: the name-zone's 390px-wide coordinate space (copied directly from the mockup's own full-bleed 390px canvas) didn't account for this site's page shell having 24px of padding on each side, so the rightmost callout was being clipped against the viewport edge. Fixed by giving `.nameZoneScale` a negative inline margin at phone width so it bleeds to the viewport edge, matching the mockup's intent, while leaving the page's normal padding in place everywhere else.
- A stale `next start` server (an earlier backgrounded process still bound to port 3000) briefly caused a badly broken screenshot — an SVG icon rendered at ~20x its intended size. Root-caused by checking for a second listener on port 3000, not by patching code; killed all node processes, cleared `.next`, rebuilt, and the fresh server rendered correctly. No code defect — noted here so a future session doesn't mistake a stale server for a real bug.
